# grove-keys · a Hyper key, launchers and the AeroSpace bindings in one Grove app

**Status:** design for review, 2026-11-10
**Builds on:** [2026-11-10-aerospace-design.md](2026-11-10-aerospace-design.md) (the bindings it takes over), [2026-11-10-grove-themes-design.md](2026-11-10-grove-themes-design.md) (the app pattern and the Grove look)
**Comes before:** the SketchyBar top bar
**Mockups:** `artifacts/grove-keys/gui-mockups/window.html` (private page https://claude.ai/artifact/EtLGo8PSZYVqz4GeQxn3MT), approved 2026-11-10

## 1. Goal

Grove Keys is a menu bar app with a window. It turns Caps Lock into a Hyper key (hold = ⌃⌥⇧⌘, tap = Escape), opens apps with Hyper + a letter, shows a cheat sheet while Caps Lock is held, and owns every AeroSpace binding plus the per-Mac monitor assignments. All of it lives in one file, `keys.toml`, which the GUI edits and which can also be edited by hand.

**Success looks like this:**
- After `grove install` (and granting Accessibility and Input Monitoring once), Grove Keys runs at login and Caps Lock acts as Hyper: holding it with a key sends ⌃⌥⇧⌘+key; tapping it alone sends Escape.
- Holding Caps Lock alone for half a second shows the cheat sheet; releasing hides it.
- On day one AeroSpace behaves exactly as now (the same Option shortcuts and service mode), but its bindings come from `keys.toml`.
- Adding a launcher or a binding in the window takes effect at once, without a Save button and without restarting AeroSpace by hand.
- Hand edits to `keys.toml` are picked up when the file is saved.
- `grove check` reports `96-keys-app` ok.

## 2. Decisions

| Topic | Decision | Why |
| --- | --- | --- |
| Scope | Hyper key, tap-for-Escape, launchers, cheat sheet, AeroSpace bindings, per-Mac monitors | Chosen by the user. |
| Default bindings | Today's Option shortcuts, unchanged; the Hyper layer starts empty | The user will move things to Hyper later, in grove-keys. |
| CLI | None for people. The file is the command-line interface | Chosen by the user. One internal flag exists for grove (§8). |
| Source of truth | One tracked file, `grove-dotfiles/config/grove-keys/keys.toml` | Chosen by the user. |
| AeroSpace config | Generated: `aerospace.base.toml` (tracked) + bindings and monitors from `keys.toml` → `aerospace.toml` (untracked) | AeroSpace has no include. Same tracked-input, generated-output pattern as the grove-themes templates. |
| Engine | `hidutil` maps Caps Lock to F18; an event tap in the app turns F18 into Hyper/Escape | Chosen by the user over Karabiner-Elements: one app, no third-party driver. |
| GUI | Two tabs, Keyboard (map per layer) and Bindings (grouped list); menu bar item; cheat sheet panel | Chosen by the user; mockups approved. |
| Look | Follows the current scheme like Grove Themes (look B, JetBrains Mono, hidden title bar) | Consistency across Grove apps. |
| Machine identity | `scutil --get LocalHostName` (e.g. `Test-Mac`) | Stable, readable, already unique per Mac. |

## 3. Out of scope

- Moving any shortcut to Hyper (the user does that later in the app).
- Other Hyper keys than Caps Lock, Caps Lock as a caps toggle, per-app bindings, chords and sequences.
- Keyboard layouts other than US ANSI in the drawn keyboard (`key-mapping.preset = 'qwerty'`).
- The bar (SketchyBar) and anything it shows.

## 5. `keys.toml`

```toml
# Grove Keys. Edit here or in the Grove Keys window; both write this file.

[hyper]
key = "caps_lock"          # only caps_lock for now
tap = "escape"             # "escape" or "none"
tap_ms = 200               # a press shorter than this, with no other key, is a tap
cheatsheet_ms = 500        # hold Caps Lock alone this long to show the cheat sheet; 0 = off
enabled = true             # false = Caps Lock is left alone

[launch]                   # Hyper + key → app bundle ID
# t = "com.mitchellh.ghostty"

[aerospace.main]           # AeroSpace syntax; "hyper-" means cmd-ctrl-alt-shift-
alt-1 = "workspace 1"
# … today's main-mode bindings, unchanged …
alt-shift-semicolon = "mode service"

[aerospace.service]
esc = ["reload-config", "mode main"]
# … today's service-mode bindings, unchanged …

[monitors."Test-Mac"]   # workspace → "main" | "secondary" | "built-in" | a display name
```

- **Keys** in `[launch]` are AeroSpace key names (`t`, `1`, `semicolon`, `slash`…), so one vocabulary covers the whole file.
- **`[aerospace.<mode>]`** becomes `[mode.<mode>.binding]` with the same keys and values; `hyper-` expands to `cmd-ctrl-alt-shift-`. Values are a string or an array of strings, as in AeroSpace.
- **`[monitors."<LocalHostName>"]`** for this Mac becomes `[workspace-to-monitor-force-assignment]`. Sections for other Macs are kept and ignored. No section, or an empty one, means no assignment (everything on the main screen).
- **TOML subset** read and written by GroveKeysCore: comments, `[table]` and `[a.b]` / `[a."quoted"]` headers, bare and quoted keys, strings, string arrays, integers, booleans. Anything else is an error with its line number.
- **Writing.** The GUI rewrites the file in a fixed order (hyper, launch, aerospace modes in file order, monitors). Comment lines are kept with the line below them, and a section's own comments stay with it; trailing comments on a value line are kept. Values are written in AeroSpace's style (`'…'` quoting is read but `"…"` is written).

## 6. Hyper engine

- **Mapping.** On start, once the event tap is running, the app sets `hidutil property --set '{"UserKeyMapping":[{"HIDKeyboardModifierMappingSrc":0x700000039,"HIDKeyboardModifierMappingDst":0x70000006D}]}'` (Caps Lock → F18). It sets it again on wake and when a keyboard is connected (IOHIDManager matching), because new devices start unmapped. On quit, *Pause Hyper*, or `enabled = false` it clears the mapping. The mapping never stays on while the tap is off, so Caps Lock is never dead.
- **Event tap.** A session event tap on keyDown, keyUp and flagsChanged. A pure state machine in GroveKeysCore decides, from (event, time):
  - F18 down → *held*; F18 itself is swallowed.
  - While held, another key down/up → add ⌃⌥⇧⌘ to its flags; the press counts as "used".
  - F18 up within `tap_ms`, not used → post Escape (keyDown + keyUp, keycode 53).
  - Held `cheatsheet_ms` with no other key → show the cheat sheet; F18 up hides it and sends nothing.
  - If the tap is disabled by timeout or user input, the app re-enables it at once.
- **Launchers** run before pass-through: Hyper + a `[launch]` key opens the app (or brings it forward) with NSWorkspace and the keystroke is swallowed. Any other Hyper key goes on as ⌃⌥⇧⌘+key, so AeroSpace's `hyper-…` bindings fire.
- **Known limit.** macOS stops event taps while a secure text field (a password box) has focus; Hyper and tap-for-Escape do nothing there. Option shortcuts are unaffected.
- **First plan task is a spike:** confirm on this Mac that AeroSpace's hotkeys fire for ⌃⌥⇧⌘ added by the tap, and that the tap needs exactly Accessibility + Input Monitoring. If AeroSpace doesn't see the added flags, stop and revisit the engine choice with the user.

## 7. The GUI

As in the mockups.

- **Menu bar item** (key glyph): *Open Grove Keys* (⌘,), *Show cheat sheet*, *Pause Hyper* / *Resume Hyper*, *Quit*. A missing permission turns the glyph orange and puts a line at the top of the menu naming it, with *Open Settings* (deep link to that Privacy pane).
- **Window**, hidden title bar, two tabs:
  - *Keyboard*: the drawn MacBook keyboard and a layer picker. Layers are the modifier sets in use: Hyper, Option, Option+Shift, each AeroSpace mode other than main (Service), plus any other modifier combination that has a binding. Each bound key shows a short label and the kind's tint: workspace green, focus/move aqua, launcher blue, layout/resize yellow, mode/service orange; free keys dim. Click or Enter on a key opens the popover: *Launcher* (Hyper layer only; app picker from /Applications and ~/Applications) · *AeroSpace* (command list: workspace N, move-node-to-workspace N, focus, move, resize, layout, mode, close, reload-config…, or free text) · *None* (removes it). Short labels come from a fixed table per command; free text shows its first word.
  - *Bindings*: groups for Hyper key (on/off, tap action, the two timings), Launchers, one per AeroSpace mode, and Monitors for this Mac. Rows are shortcut recorder · action · remove; runs of 1…9 fold into one row until expanded. Monitors lists the displays connected now and gives each workspace 1–9 a menu: main · secondary · built-in · each connected display's name.
  - Keyboard: arrows or Ctrl+H/J/K/L move, Enter opens, Esc closes the popover or the window.
- **Conflicts.** A launcher key that is also a `hyper-` AeroSpace binding: the launcher wins; both rows show an orange mark. A recorder press that matches an existing binding in the same layer asks *Replace* / *Cancel* inline.
- **Cheat sheet.** A non-activating borderless panel centred on the screen with the focused window, showing the Hyper layer read-only on a dimmed backdrop.
- **Colours** come from the current scheme via grove-themes' state file, as in Grove Themes, and update on a scheme switch.

## 8. Saving and AeroSpace

Every change in the window, and every save of the file by hand (file watcher), runs the same path:

1. Parse `keys.toml`. On error: keep the last good config running, show the red line (`keys.toml line 14: …`) under the tabs and an orange menu glyph; touch nothing else.
2. Apply Hyper settings and launchers in the app.
3. Render `aerospace.toml` = a generated-file header + `aerospace.base.toml` + the `[mode.*.binding]` tables + this Mac's monitor table. If the result equals the file on disk, stop.
4. Keep the old file, write the new one, run `aerospace reload-config --dry-run`. If it fails, put the old file back and show AeroSpace's message in the red line. Otherwise run `aerospace reload-config`.
5. If AeroSpace isn't running, steps 3–4 still write the file (AeroSpace reads it when it starts), the dry run is skipped, and nothing is shown.

The window writes `keys.toml` atomically (temp file + rename in the same folder), then runs the path; the watcher ignores the app's own write.

`GroveKeys --render-aerospace` runs step 3 once and exits (non-zero with the message on error). It exists for grove's module and tests only and isn't documented as a user CLI.

## 9. grove module `96-keys-app`

Modelled on `97-themes-app`:
- `apply`: `swift build -c release` in `grove-keys/app`, assemble and ad-hoc sign `~/Applications/Grove Keys.app` (bundle ID `com.projectgrove.keys`, `LSUIElement`), write the stamp, run `--render-aerospace`, write and load the LaunchAgent `com.projectgrove.keys` (RunAtLoad, KeepAlive on crash, the same PATH as Grove Themes), then open the Accessibility and Input Monitoring panes if the app reports either missing.
- `check`: app built from the current source (stamp), LaunchAgent written and loaded, `aerospace.toml` current with `keys.toml` (re-render and compare), permissions granted (the app writes them to its state file), mapping present in `hidutil property --get UserKeyMapping` while enabled. Each failure gets its own message.
- Fakes for `swift`, `launchctl`, `codesign`, `hidutil`, `scutil` and the apps and agents folders, like 97's.

Other grove changes:
- `config/aerospace/aerospace.toml` → `aerospace.base.toml` without `[mode.*]` tables; the bindings move to `keys.toml` unchanged. `config/.gitignore` adds `!/grove-keys/` and `/aerospace/aerospace.toml`.
- `98-aerospace` checks that `aerospace.toml` exists and points to 96 when it doesn't.
- The Grove Keys window floats in AeroSpace (`on-window-detected` for `com.projectgrove.keys` in the base file).
- The Brewfile gains nothing.

## 10. Errors

| Situation | What happens |
| --- | --- |
| Input Monitoring or Accessibility missing | No tap, no mapping (Caps Lock stays Caps Lock); orange glyph and menu line; window shows a banner with *Open Settings*. Retried every 2 s until granted. |
| Event tap disabled by the system | Re-enabled at once; if that fails three times in a minute, the mapping is cleared and the menu says so. |
| App crashes | LaunchAgent restarts it. The mapping may remain until it does (seconds); a reboot also clears it. |
| `keys.toml` invalid | Last good config keeps running; red line with the line number; nothing written. |
| AeroSpace rejects the render | Previous `aerospace.toml` restored; red line with AeroSpace's message. |
| AeroSpace not installed or not running | File written, no reload, no message. |
| No section for this Mac | No monitor assignment; the Monitors group says "Not set for this Mac yet" and creates the section on first change. |
| Launcher app missing | Hyper+key does nothing; its row shows the app as missing (grey, "not installed"). |
