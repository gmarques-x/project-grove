# Bar Cloud Pill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A cloud pill in the Grove bar that says whether iCloud Drive and OneDrive have finished syncing, with a dropdown per provider listing what's pending or wrong, opening the folder in Grove Explorer and opening the provider's settings.

**Architecture:** Grove Keys tracks sync state off the main thread: FSEvents on each cloud root plus a pending set of changed files re-read from URL resource values until they settle, after one metadata-only first pass that never materialises anything. Pure rules (item state, ignore list, stuck rule, summaries, words, bar file) live in GroveKeysCore; the provider naming rule moves from Grove Explorer into grove-themes' GroveThemesCore so both apps share it. The bar shows a `cloud` item fed by `$GROVE_STATE/cloud`; the dropdown is a Grove Keys bar panel.

**Tech Stack:** Swift 6, SwiftUI + AppKit, CoreServices FSEvents, Swift Testing; bash + bats for SketchyBar.

**Spec:** grove-dotfiles/docs/specs/2026-11-14-bar-cloud-design.md

## Global Constraints
- Order `cpu/mem · cloud · vpn · wifi+bt · sound · power · clock`; item `cloud`, pill `pill.cloud`, event `cloud_change`, panel `cloud`; state file `$GROVE_STATE/cloud` with exactly one of `checking`, `synced`, `syncing <n>`, `problem`, written only on change, removed on stop; missing/unreadable file → grey cloud.
- Icons from `icons/make.swift`: `cloud-checking` (grey), `cloud-synced` (green), `cloud-syncing` (yellow), `cloud-problem` (red), `cloud-off` (grey, missing file), dark and light; the count in a fixed-width label, hidden at 0.
- Pending = uploading, or ubiquitous and not uploaded, or downloading in progress; files only. Online-only (`notDownloaded`) and `.downloaded` are never pending. Error or unresolved conflict = problem. Ignored names: `.DS_Store`, `._*`, `*.nosync`, `~$*`, `*.tmp`. Pending 30 min with no change → problem "not uploading for 30 min". Re-read every 5 s for 2 min, then every 60 s; cap 2,000 (count "2000+"). Fresh reads (no cached resource values).
- Never materialise: the walking/expansion thread sets `setiopolicy_np(IOPOL_TYPE_VFS_MATERIALIZE_DATALESS_FILES, IOPOL_SCOPE_THREAD, IOPOL_MATERIALIZE_DATALESS_FILES_OFF)` and skips directories with `SF_DATALESS`; only resource values / stat are read.
- Copy: "Up to date", "Uploading N files · Downloading M" (parts left out at 0), "N problems" / "1 problem", "OneDrive isn't running", "Grove Keys can't see OneDrive's files", "Open in Grove Explorer", "Settings…", "Open OneDrive's settings from its activity window", "not uploading for 30 min".
- Links: `groveexplorer://open?path=<percent-encoded absolute path>`; iCloud settings `x-apple.systempreferences:com.apple.systempreferences.AppleIDSettings` (fallback: System Settings); OneDrive bundle id `com.microsoft.OneDrive`.
- No real file or account names in committed fixtures, samples or docs (public repo). Never open, move or download the owner's cloud files.
- grove-ui skill. GroveKeys binary ONLY with `--render-panel`, `--render-keys`, `--render-aerospace`, `--check-menu`; GroveExplorer only `--render`/`--audit-accessibility`/`--time-list`; never launch, quit or install apps; never reload the real SketchyBar. Renders to a private folder. Never commit them; never touch `config/grove-keys/keys.toml`.
- Commits: `area: summary` + body + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, by explicit path.

## Review Focus
1. A huge OneDrive (tens of thousands of items, many online-only folders) must not spike CPU or network at login: the first pass is rate-capped and skips dataless folders (Task 3 test with a dataless stand-in + a throughput check in the report).
2. A provider folder that disappears while tracked (OneDrive signed out, folder removed) must drop its section and pending items, not leave a stale problem (Task 2 test; Task 3 step).
3. A burst of thousands of FSEvents (unzipping into OneDrive) must coalesce, not queue thousands of reads at once (Task 3 step: event batching + the cap).
4. Grove Keys quitting mid-sync leaves no stale `syncing` file (removed on stop; Task 3).
5. The dropdown open while counts change must not jump or flicker rows (Task 4: stable row order by id within each group).
